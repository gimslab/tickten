# 스트레칭/운동용 인터벌 비프 타이머 기획 및 기술 조사

## 1. 개요 및 배경
- **목적**: 스트레칭, 플랭크 등 자세 유지 운동 시 스마트폰 화면을 계속 쳐다보지 않고, **청각적 피드백(비프음 및 틱 소리)**만으로 경과 시간을 직관적으로 인지할 수 있는 타이머.
- **주요 사용 시나리오**:
  - 30초, 60초 등 목표 시간 동안 자세 유지
  - 10초마다 울리는 비프음을 통해 "현재 10초, 20초, 30초..."가 경과했음을 자연스럽게 파악
  - 초 단위의 미세한 틱 소리로 타이머가 멈추지 않고 진행 중임을 감지

---

## 2. 핵심 요구사항 명세

### 2.1 오디오 피드백 (Audio Feedback)
1. **메인 인터벌 비프 (Interval Beep)**
   - 기본 주기: **10초** (사용자가 5초, 10초, 15초, 30초 등 원하는 단위로 설정 가능)
   - 소리 특성: 운동에 방해되지 않으면서도 주위 소음 속에서 뚜렷하게 들리는 명확한 톤 (예: 880Hz / 1000Hz 정현파, 150~200ms)
2. **초 단위 틱 사운드 (Subtle 1s Tick)**
   - 1초마다 재생되는 아주 약한 클릭/틱 소리
   - 토글 기능: 사용자가 켜고 끌 수 있는 On/Off 스위치 제공
3. **오디오 볼륨 및 독립 제어**
   - 시스템 볼륨 외에 앱 내 마스터 볼륨 또는 비프/틱 개별 음량 조절 가능 여부 고려

### 2.2 사용자 인터페이스 (UI/UX)
1. **미니멀 & 하이 콘트라스트 UI**
   - 운동 중 멀리서 보아도 현재 시간(초)을 한눈에 식별할 수 있는 거대한 폰트
   - 단순한 원터치 버튼: **시작(Start) / 일시정지(Pause) / 초기화(Reset)**
2. **간편한 설정 패널**
   - 메인 비프 주기 조절 (기본 10초, +5초/-5초 스텝 버튼 또는 직관적인 슬라이더)
   - 1초 틱 소리 켜기/끄기
   - 화면 켜짐 유지(Wake Lock) 상태 표시

## 3. 웹앱(PWA) vs 네이티브 앱 비교 분석

| 비교 항목 | 웹앱 (PWA / Responsive Web) | 네이티브 앱 (iOS / Android) |
| :--- | :--- | :--- |
| **설치 편의성** | **무설치**, URL 접속 즉시 실행 (홈 화면 추가 지원) | 앱스토어 / 플레이스토어 다운로드 및 설치 필수 |
| **배포 및 유지보수**| 즉각적인 업데이트 배포 가능, 플랫폼 심사 없음 | 스토어 심사 및 검수 기간 소요 |
| **정밀 오디오 재생** | **Web Audio API** (`OscillatorNode`)로 지연 없이 정확한 사운드 합성 가능 | 플랫폼 네이티브 오디오 플레이어 |
| **화면 켜짐 유지** | **Screen Wake Lock API** 지원 (모바일 크롬, 사파리 16.4+ 지원) | 네이티브 플래그 (`FLAG_KEEP_SCREEN_ON`, `isIdleTimerDisabled`) |
| **백그라운드 동작** | **제약 있음**: 화면이 잠기거나 백그라운드 전환 시 브라우저 스로틀링으로 타이머 지연/정지 가능 | 백그라운드 서비스/오디오 세션으로 완벽 지원 |
| **진동 (Haptic)** | 안드로이드(`navigator.vibrate`) 지원, **iOS 사파리 미지원** | iOS (CoreHaptics), 안드로이드 (Vibrator) 모두 지원 |
| **무음 모드 우회** | 아이폰 하드웨어 무음 스위치 상태에 따라 소리 제한 가능성 있음 | `AVAudioSessionCategoryPlayback` 설정으로 무음 스위치 우회 가능 |

## 4. 기술 분석 및 1단계(웹앱) 채택 타당성

### 4.1 1단계로 웹앱이 최적인 이유
1. **즉각적인 접근성**: 별도 앱스토어 설치 과정 없이 모바일 브라우저로 바로 실행 가능
2. **Web Audio API의 장점**:
   - 외부 mp3/wav 파일 네트워크 로딩 없이 브라우저 자체 오실레이터로 딜레이 0ms의 깨끗한 톤(Sine/Triangle wave) 합성
   - 오디오 파일 다운로드 실패나 캐시 문제 원천 차단
3. **Screen Wake Lock API 활용**:
   - 운동 중 화면을 켜두는 형태로 거치해두고 쓸 경우, 화면 잠금 없이 지속 동작 가능
4. **PWA (Progressive Web App) 기능**:
   - Manifest + Service Worker 적용 시 오프라인에서도 작동하며 홈 화면 아이콘 제공

### 4.2 네이티브 앱으로의 확장이 필요한 시점
- 사용자가 "스마트폰 화면을 완전히 끄고(잠금 상태) 주머니에 넣은 채 10초 비프를 듣고 싶다"고 요구할 때
- iOS 기기에서 햅틱(진동) 피드백이 반드시 필요할 때
- $\rightarrow$ 필요 시 추후 Capacitor 또는 React Native로 래핑하여 스토어 배포 가능

---

## 5. 결론 및 구현 방향
- **선택 방향**: **1단계 모바일 최적화 반응형 PWA(Progressive Web App)** 구현
- **기술 스택**:
  - 현대적이고 가벼운 프론트엔드 환경 (HTML5, Modern CSS, Vanilla TypeScript/JavaScript 또는 React + Vite)
  - **Web Audio API**: 비프음 및 초 틱음 정밀 합성 엔진
  - **Screen Wake Lock API**: 운동 중 화면 꺼짐 방지
  - **PWA Service Worker / Web App Manifest**: 홈 화면 추가 및 오프라인 구동
